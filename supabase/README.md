# تفعيل مزامنة MyOS الاختيارية

لا تحتاج الوظائف المحلية أو النشر على GitHub Pages إلى حساب Supabase. هذا الدليل يربط نسخ الملاحظات والملفات النصية وحفظ المعارك وتقدّم المراحل بين أجهزتك. الصور الشخصية لا تدخل في النسخ السحابية.

1. افتح https://supabase.com/dashboard وأنشئ حسابًا ومشروعًا جديدًا. اختر اسمًا ومنطقة، واحتفظ بكلمة مرور قاعدة البيانات في مكان خاص؛ لا تدخلها في MyOS.
2. انتظر جاهزية المشروع، ثم افتح **SQL Editor → New query**، وانسخ محتوى [schema.sql](schema.sql) كاملًا وشغّله. ينشئ جدول النسخ وسياسات RLS التي تسمح لكل حساب بالوصول إلى نسخته وحده، ودالة رفع تتحقق من إصدار النسخة قبل استبدالها. يمكن إعادة تشغيل الملف.
3. في **Authentication → Providers** فعّل **Email** وتسجيل الحسابات. عند تفعيل تأكيد البريد، يجب تأكيد رسالة التسجيل قبل الدخول. اضبط **Authentication → URL Configuration → Site URL** إلى `https://magdyaqel.github.io/MyOS/` حتى تعود رسائل التأكيد إلى التطبيق.
4. من نافذة **Connect** أو **Project Settings → API Keys / Data API** انسخ **Project URL** و**Publishable key** الذي يبدأ بـ `sb_publishable_`. يمكن استخدام مفتاح **anon** القديم أيضًا. لا تستخدم `sb_secret_` أو `service_role`؛ يرفضهما التطبيق. المفتاح العام معرّف للمشروع، وحماية البيانات تعتمد على تسجيل الدخول وسياسات RLS المرفقة.
5. افتح MyOS ثم **المزامنة السحابية**، وأدخل عنوان المشروع والمفتاح العام واضغط **حفظ إعداد الخدمة**. أنشئ حسابًا بالبريد وكلمة المرور، وأكّد بريدك إن طُلب، ثم سجّل الدخول.
6. اضغط **فحص النسخة السحابية** ثم **رفع نسخة هذا الجهاز**، وراجع التفاصيل قبل التأكيد. على جهازك الآخر، أدخل إعداد المشروع نفسه وسجّل بالحساب نفسه، ثم اضغط **استعادة نسخة السحابة** وراجع التأكيد.

المزامنة يدوية؛ لا تدمج نصوصًا متعارضة تلقائيًا. عند وجود إصدار أحدث، يرفض التطبيق الرفع ويطلب فحص السحابة. الاستعادة تستبدل مجموعات البيانات الواردة في النسخة فقط، وتغلق التطبيقات الأخرى أولًا لمنع الحفظ القديم فوق النسخة المستعادة. يحتفظ الجهاز بنسخة واحدة للتراجع عن آخر استعادة. نزّل ملفاتك المهمة بصيغة TXT قبل الاستبدال.

يحفظ المتصفح عنوان المشروع والمفتاح العام؛ تبقى جلسة الدخول في الذاكرة فقط، وتنتهي محليًا عند إغلاق نافذة المزامنة أو إعادة تحميل الصفحة. لا تُحفَظ كلمة المرور أو رموز الدخول في localStorage أو النسخ المرفوعة.

## التحقق بعد الإعداد

- اكتب ملاحظة تجريبية وارفعها، ثم استعدها في متصفح آخر بالحساب نفسه.
- سجّل بحساب مختلف وتحقق من أنه لا يرى نسخة حسابك الأول.
- افتح جهازين بالحساب نفسه، وافحص النسخة على كليهما. ارفع من الأول ثم حاول الرفع من الثاني دون فحص جديد؛ يجب ظهور تعارض بدل استبدال صامت.
- عند `403` راجع تنفيذ السياسات. عند `400/404` راجع تنفيذ SQL وتفعيل Email وتأكيد البريد. يحتاج الاتصال إلى الإنترنت، وقد تنطبق حدود الخطة التي تختارها في Supabase.

اختبارات المستودع تتحقق من عميل المصادقة والنسخ والتعارض والاستعادة والتراجع باستخدام خدمة محاكاة. لم يُنشأ مشروع حقيقي ولم تُنفّذ السياسات على خدمة Supabase فعلية ضمن هذا التحديث؛ يلزم إجراء التحقق أعلاه بعد إنشاء مشروعك.

تم التحقق محليًا من تنفيذ SQL وإعادة تشغيله وعزل الحسابات ورفض الوصول المجهول والتعارض باستخدام PostgreSQL عبر PGlite 0.5.10 مع محاكاة `auth.uid()`. لا يغني ذلك عن التحقق على مشروع Supabase الفعلي.
