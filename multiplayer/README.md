# مواجهة MyOS عبر الويب لشخصين

الواجهة على [GitHub Pages](https://magdyaqel.github.io/MyOS/)، وخادم الغرف المنشور هو `https://myos-arena.iugteacher.workers.dev` على Cloudflare Workers مع Durable Objects. يحدد `public/multiplayer.json` عنوان الاتصال العام. لا يحتاج اللاعبون إلى Supabase أو إنشاء حساب؛ يستخدم مالك المشروع حساب Cloudflare لنشر الخادم وتحديثه.

عند تحديث نسخة قديمة مثبّتة، افتح **تثبيت MyOS → تطبيق التحديث المتاح** ليستخدم الموقع إعداد الخادم الجديد. لا تمسح بيانات الموقع لتحديثه.

عنوان الخادم الافتراضي مضمّن في نسخة البناء من `public/multiplayer.json`، ويظهر حتى إذا بقي إعداد قديم فارغ في ذاكرة العمل دون إنترنت أو تعذّر تنزيل الإعداد. يجلب التطبيق الإعداد الحديث دون تجاوز العنوان الذي تكتبه أو عنوان خادم دعوة صديقك. تعديل `public/multiplayer.json` يحتاج إعادة بناء الواجهة ونشرها لتحديث العنوان المضمّن أيضًا. الخانة الفارغة أو العنوان غير الصحيح يظهران رسالة عربية قبل إرسال أي طلب لإنشاء غرفة.

## التشغيل المحلي

```sh
npm ci
npm run dev -- --port 5173 --strictPort
npm run dev:multiplayer
npm run test:multiplayer
```

أمر الخادم يستخدم Wrangler 4.151.1 المثبت في المشروع، ويضع إعداداته وسجلاته داخل `.wrangler-user/`، وهي مستثناة من Git. إعداد التطوير يسمح بأصل Vite المحلي فقط ويلغي انتظار إنشاء الغرف لتسهيل الاختبار. إعداد النشر يسمح بـ `https://magdyaqel.github.io` ويطبق انتظار عشر ثوانٍ لكل عنوان IP بين إنشاء غرفتين. لا يحتاج التشغيل المحلي إلى مفتاح حساب.

## نشر الخادم

1. جهّز حساب Cloudflare مع عنوان فرعي لـ Workers. أنشئ API Token مخصصًا للحساب بصلاحيتي **Workers Scripts: Edit** و**Account Settings: Read**. يحتاج النشر إلى الصلاحية التي تسمح بإنشاء Worker وربط Durable Objects في الحساب.
2. أدخل `CLOUDFLARE_API_TOKEN` كسر و`CLOUDFLARE_ACCOUNT_ID` كمتغير في **إعدادات البيئة**. لا ترسلهما في المحادثة ولا تضع المفتاح في ملفات المستودع أو الموقع. معرّف الحساب موجود في لوحة Cloudflare. يمكن للمطور على جهازه استخدام متغيرات البيئة نفسها أو تسجيل الدخول بواسطة `node scripts/arena-worker.mjs login`.
3. نفّذ `npm run deploy:multiplayer`. ينشئ Wrangler خادم `myos-arena` وربط `ROOMS` وترحيل SQLite المرفق، ويعرض عنوانًا مثل `https://myos-arena.your-subdomain.workers.dev`.
4. احفظ العنوان العام فقط: `node scripts/configure-arena.mjs https://myos-arena.your-subdomain.workers.dev`، ثم `npm run build` وانشر الواجهة. إعداد `public/multiplayer.json` عنوان عام وليس مفتاح حساب. يمكن أيضًا إدخال العنوان يدويًا في نافذة اللعب؛ رابط الدعوة يحمل العنوان مع رمز الغرفة.
5. إذا غيرت نطاق الواجهة، أضف أصل HTTPS الصحيح إلى `ALLOWED_ORIGINS` في إعداد Worker وأعد نشره. لا يلزم مسار `/MyOS/` في قائمة الأصول؛ الأصل هو البروتوكول والمضيف فقط.

إعداد GitHub Actions ينشر الواجهة؛ نشر Worker يتم بالأمر المنفصل أعلاه من البيئة المتصلة بالحساب. التغييرات في قواعد المحاكاة المشتركة تحتاج إعادة نشر الخادم أيضًا. استخدام الغرف والاتصالات ومدة تشغيل Durable Objects يدخل ضمن حصص خطة Cloudflare؛ راقب الاستخدام في حسابك. هذا الإصدار مخصص للمواجهات الخاصة لشخصين، ولا يحتوي نظام بحث عام عن خصوم.

## اللعب

- افتح **اللعب عبر الويب**، واختر خريطة وأنشئ غرفة خاصة.
- انسخ رابط الدعوة وأرسله بنفسك إلى اللاعب الثاني. ينضم من الرابط أو الرمز، ثم يضغط الطرفان **جاهز للمواجهة** ويفتحان ساحة اللعب.
- يبدأ الطرفان بالموارد والوحدات نفسها على جهتين متقابلتين. ترى جيشك باللون الأزرق دائمًا؛ اللاعب الثاني يبدأ من يمين الخريطة. لا توجد موجات آلية أو ترقيات حملة في هذا الوضع.
- البناء والتدريب والحركة والتشكيلات والدورية والحماية والصيانة وتحريك القيادة ونقطة التجمع تعمل عبر الخادم. تحتاج للهجوم إلى كشف الخصم؛ لا تصل مواقع وحداته غير المكتشفة إلى متصفحك.
- توقف المعركة عند انقطاع أحد الطرفين. استأنف من **استئناف الاتصال السابق** في التبويب نفسه؛ رمز المقعد محفوظ في `sessionStorage` فقط. بعد 60 ثانية من غياب طرف تُحسب خسارته. الغرفة تنتهي بعد ساعتين. إغلاق تبويبك قد يفقد رمز الاستئناف؛ رابط الدعوة وحده لا يسترد مقعدًا محجوزًا.
- لا يكتب هذا الوضع فوق حفظ المعارك أو تقدم الحملة الفردية. تُحفظ حالة الغرفة في Durable Object كل خمس ثوانٍ وعند تغييرات الاتصال؛ قد تفقد آخر ثوانٍ عند إعادة تشغيل الخادم.

## نموذج الاتصال والتحقق

الخادم يحسب القتال والموارد والتحرك، ويقبل أوامر محدودة بأرقام ووجهات صحيحة ووحدات مملوكة للمقعد المصادق عليه. رموز الغرفة والمقاعد عشوائية، ولا يوجد أكثر من مقعدين. مفتاح المقعد يرسل في رسالة المصادقة داخل WebSocket ولا يدخل رابط الدعوة أو URL الاتصال. لا تضع مفتاح Cloudflare في الواجهة. تُحد الرسائل بـ 4 كيلوبايت و25 رسالة في الثانية لكل اتصال، مع مهلة للمصادقة وعدد اتصالات محدود. هذه ضوابط أساسية وليست نظامًا متكاملًا لمكافحة إساءة الاستخدام.

`npm test` يتضمن اختبارات للمحاكاة العادلة وملكية الأوامر وضباب الحرب وتحريك مقري الطرفين والنتيجة. `npm run test:multiplayer` يشغّل اختبارًا فعليًا بمتصفحين منفصلين على Worker محلي، ويتحقق من الدعوات والجاهزية والموارد ورفض اللاعب الثالث والانقطاع والعودة، ثم يفحص رفض أصول الويب غير المسموحة. الاختبار المحلي لا يثبت نشر الخادم على Cloudflare أو أداء الاتصال عبر شبكتين فعليتين؛ يلزم فحص ذلك بعد النشر.


### قواعد الغرفة في 4.2

يمكن للمضيف تحديد `startingCash` (عدد صحيح من 1000 إلى 100000) عند إنشاء الغرفة، ويبدأ اللاعبان بالقيمة نفسها. تبقى القيمة الأصلية في حفظ الغرفة وتستخدم لإعادة الجولة. اسم القائد يرسل في رسالة المصادقة الأولى، ويقتصر على 32 حرفًا ويعرض كنص.

بعد جاهزية الطرفين يرسل الخادم مرحلة `countdown` لمدة ثلاث ثوانٍ؛ الأوامر مرفوضة خلالها. رسائل `ping`/`pong` تقيس زمن الرحلة في المتصفح. `surrender` يحسب خسارة المرسل، و`rematch` يسجل طلب إعادة بعد نهاية الجولة؛ عند موافقة الطرفين المتصلين يعيد الخادم الجيش والمال والرؤية ويبدأ العد من جديد، دون تغيير رموز المقاعد أو حفظ الحملة الفردية.

الاختبار المحلي يستخدم متصفحين مستقلين وخادم Durable Objects حقيقيًا عبر Wrangler، ويتحقق من المال والملكية والركوب والعودة بعد انقطاع، إلى جانب الاستسلام وإعادة الجولة. نشر العامل ونجاح اختبار محلي لا يثبتان اتصال جهازين عبر الإنترنت؛ يلزم تجربتهما على الموقع المنشور.
